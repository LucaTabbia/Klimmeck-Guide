<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → backend (`logout`, autenticata) | invalidazione lato server, può fallire o non rispondere |
| refresh in volo ↔ logout locale | concorrenza interna |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-26 | Elevation of Privilege | sessione zombie dopo logout | mitigate | `_epoch++` prima del teardown; il refresh in volo verifica l'epoch prima di persistere/applicare; test dedicato |
| T-11-27 | Information Disclosure | access JWT ancora valido server-side dopo logout (≤ 15 min, BE D-27) | mitigate | L'app lo scarta subito (memoria a null, `getAccessToken()` → null); la revoca server-side resta del backend |
| T-11-28 | Denial of Service | logout bloccato offline | mitigate | Passo 1 best-effort con timeout 4 s (D-13); i passi 2–5 sempre eseguiti |
| T-11-29 | Information Disclosure | account bleed A → B | mitigate | Teardown completo (client GraphQL ricreato in 11-08/11-10, storage svuotato, utente azzerato); test account switch |
| T-11-30 | Tampering | doppio refresh dal retry reattivo | mitigate | `recoverFromUnauthorized` confronta il token rifiutato e passa dal single-flight |
</threat_model>
