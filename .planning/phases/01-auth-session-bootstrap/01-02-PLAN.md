    **State machine:**
    - Stato iniziale emesso allo stream: `AuthBootstrapping()`
    - `bootstrap()`: legge refresh token → se assente emette `Unauthenticated(initial)`; se presente chiama `api.validate`; 200 → `Authenticated(userId)`; `RevocationException` → chiama `handleRevocation()` (che emette `Unauthenticated(sessionExpired)`); errore transitorio (network/5xx) → rilancia per lasciare gestione al SplashCubit (retry).
    - `login()`: (1) genera PKCE+state, (2) build URL, (3) `webAuthenticator(url, callbackUrlScheme: 'klimmeck')`, (4) parse `code`+`state`, valida `state` contro quello generato, (5) `exchangeCode`, (6) chiama `validate` per ottenere `userId`, (7) `storage.saveTokens`, (8) schedule proactive refresh timer, (9) emette `Authenticated`. `PlatformException(CANCELED)` → lancia `OAuthCancelledException` (SignInCubit la tratta silenziosa). Altri errori → `OAuthNetworkException`.
    - `getAccessToken()`: se in-memory token fresh (expiry > now + 60s) → return. Altrimenti → path mutex.
    - Mutex: un solo `Completer<String>?`. Il primo chiamante crea il Completer, esegue `api.refresh`, completa. I concorrenti attendono lo stesso Completer. In `finally` azzera il Completer. Se `api.refresh` lancia `RevocationException` → `handleRevocation()` + `completeError`. Errori transitivi → `completeError` senza revocation.
    - `logout({revokeOnTwitch: true})`: (1) se `revokeOnTwitch && accessToken != null` → `api.revoke(accessToken)` con timeout best-effort (5s), (2) cancella proactive timer, (3) `storage.clearAll()`, (4) clear in-memory state, (5) chiama il callback `onLogoutCompleted()` (GraphQL recreation in plan 03), (6) emette `Unauthenticated(userLogout)`. L'ordine è fisso; step 1 non blocca in caso di fallimento.
    - `handleRevocation()`: equivale a `logout(revokeOnTwitch: false)` ma emette `Unauthenticated(sessionExpired)`.
    - **Proactive timer**: dopo ogni setTokens, `Timer(expiresIn - 60s, ...)` invoca silenziosamente `getAccessToken()` per provocare refresh. Cancellato in logout/revocation.
  </behavior>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device storage ↔ app | Access + refresh token attraversano questo confine |
| app → Twitch API (HTTPS) | Exchange code + refresh + validate + revoke |
| OAuth callback (OS→app) | `klimmeck://auth?code=...&state=...` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Information Disclosure | Refresh token a riposo | mitigate | `SecureStorageService` scrive solo via `flutter_secure_storage` (Keychain/Keystore); grep-guard CI verifica assenza di `SharedPreferences` nella cartella `services/auth/` (HARDEN-01 precursor) |
| T-01-02-02 | Spoofing | OAuth callback hijacked | mitigate | PKCE S256 (`PkceGenerator`) + validazione `state` in `login()` — code rubato non scambiabile senza `code_verifier` |
| T-01-02-03 | Tampering | `state` parameter forgery | mitigate | `state` generato con `Random.secure()` 32-char; match strict in `login()`; mismatch → throw prima di `exchangeCode` |
| T-01-02-04 | Denial of Service | Race 401 → doppio refresh → silent logout | mitigate | Completer single-flight mutex in `getAccessToken()` (D-06); test di concorrenza automatico |
| T-01-02-05 | Information Disclosure | Token in log | mitigate | `avoid_print` abilitato; nessun `print(token)` in codice; `toString()` di `TwitchTokenResponse` non include i campi (override esplicito) |
| T-01-02-06 | Information Disclosure | Token in crash/analytics | accept | Nessun crash reporting integrato in v1.0; rivalutare in Phase 11 Hardening |
| T-01-02-07 | Elevation of Privilege | Client ID in repo | mitigate | `TWITCH_CLIENT_ID` via `dart-define`; verificato in plan 01 |
| T-01-02-08 | Tampering | Refresh-token replay dopo logout remoto | mitigate | `handleRevocation()` su `invalid_grant` → clearAll; validate su cold start rileva revoca esterna (AUTH-07) |
