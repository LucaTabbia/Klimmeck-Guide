## Session contract (BE Phase 17) and gate

- Contract names, stable and not negotiable by the plans (fixed by the orchestrator on 2026-11-09 with the BE Phase 17 `17-REPO-RULES.md`; nothing changes in the SDL):
  - A refused refresh keeps `extensions.code: "SESSION_REVOKED"` and adds **`extensions.reason`**: one of the `SessionRevokeReason` values **`newLogin`**, **`roleChanged`**, **`reuseDetected`**, **`userLogout`** (string enum, lower camel case); `SESSION_EXPIRED` carries no reason; a missing or unknown reason is legal and maps to the neutral notice.
  - The BE closes the WebSocket of a revoked session with close code **`4409`** and reason string = the same `SessionRevokeReason` value (e.g. `newLogin`); a `connection_init` carrying the JWT of a revoked session is closed with `4409` too. `4401` (token expired) and `4403` (missing/invalid bearer) keep their meaning.
  - The access JWT stays stateless: HTTP requests with the residual token pass until expiry (15 min). The FE never infers a revocation from a 401 alone.
- FE names fixed for the plans: `UnauthenticatedReason` gains **`replacedByNewLogin`** and **`roleChanged`** (`lib/repository/services/auth/auth_token_service.dart`); `SignInNotice` gains **`replacedByNewLogin`** and **`roleChanged`** (`lib/screens/auth/auth_gate.dart` maps them; `lib/screens/signIn/sign_in_screen.dart` renders the copy); `SessionRejected` (`lib/repository/services/auth/auth_api_exception.dart`) carries the optional `reason` parsed leniently from `extensions.reason`, with the constants `sessionRevokedReasonNewLogin = 'newLogin'` and `sessionRevokedReasonRoleChanged = 'roleChanged'`; `WsReconnectPolicy.authRejectedCloseCodes` (`lib/repository/services/graphql/ws_reconnect_policy.dart`) gains **`4409`** as `wsSessionRevokedCloseCode` (same path as `4401`: refresh before reconnect, bounded attempts); `SessionAuthTokenService._endSession` receives the mapped reason.
